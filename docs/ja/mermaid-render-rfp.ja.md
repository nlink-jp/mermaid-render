# RFP: mermaid-render

> Generated: 2026-09-28
> Status: 承認済み（2026-09-28）— 独立検証 2 本の指摘と運用者判断を反映した第 2 稿

## 1. Problem Statement

gem-agent の応答に mermaid の図が出ると、いまは罫線文字の図に変換して端末に表示している
（gem-agent ADR-0042 / ADR-0063）。この方式は表現できない構文が多く、日本語が混ざると崩れやすく、
描けずにソースを見せるだけになる場面が少なくない。運用者は図を使いたいが、この品質では使えない
ので、作業の指示に図を含めていない。lagent には図を描く経路そのものが無い。さらに、変換に使っている
`AlexanderGrooff/mermaid-ascii` はコミュニティ製で、組織の方針（組織の外で書かれたコードは出荷
しない）が定まる前に採用したものである。

端末に画像を出す仕組みは両ランタイムに既にある（`internal/termimg`、iTerm2 と kitty の方式、
gem-agent ADR-0089）。そこで、mermaid のソースを画像にするエンジンを、第三者のコードを使わずに
自前で持つ。ランタイムはトランスクリプトを描くときに mermaid のフェンスをその場で画像にし、
運用者は図を画像として端末で読める。図を描けるようになれば、運用者は作業の指示に図を含める。

想定利用者は gem-agent / lagent の運用者。利用者側の準備は要らない（既定のフォントは macOS に
最初から入っているヒラギノを使い、ネットワークも資格情報も使わない）。

## 2. Functional Specification

### 使われ方（ランタイムの描画機能であって、モデルのツールではない）

- ランタイムは、応答本文をトランスクリプトに描くとき、mermaid のフェンスを見つけてこのエンジンに
  渡し、返ってきた画像をその場に表示する。モデルに図を描くツールは与えない。システムプロンプトは
  図について何も言わない（gem-agent ADR-0063 の方針をそのまま引き継ぐ）。図を求めるのは運用者の
  作業の指示である。
- トランスクリプトに保存するのは原文のまま。画像は表示にだけ使う。
- エンジンに渡すのは、gem-agent の既存の変換表（罫線レンダラ向けに形を四角に揃え、ラベル内の
  `&` を全角にする）を**通す前の原文**。通した後を渡すと、形とラベルの文字が失われる。

### Commands / API Surface

Go ライブラリ。モジュールは `github.com/nlink-jp/mermaid-render`。

| API | 役割 |
|---|---|
| `Parse(src string) (Diagram, error)` | ソースを、描き方に依存しない図のデータにする。第 2 段階の罫線表示も同じデータを使う |
| `raster.Render(d Diagram, opts Options) (*image.RGBA, error)` | 図のデータを白地のカード状の画像にする |
| `raster.RenderSource(src string, opts Options) (*image.RGBA, error)` | 上の 2 つを続けて行う |
| `raster.LoadFont(spec FontSpec) (*Font, error)` | 指定したフォントを読む。読んだものは使い回せる |
| `raster.DefaultFont() (*Font, error)` | ヒラギノ角ゴシック W3（本文）と W6（太字）を読む |

`Options` に持たせるのは次の 2 つだけ。

- `Font` — 使うフォント。省略するとヒラギノ。
- `Scale` — 拡大率。既定は **2**（段 0 の実測で決定）。本文の文字は `Scale` 1 で 14px なので、既定では
  28px になる。

PNG への変換は呼び出し側が行う（`termimg.Payload` が受け取るのは符号化済みのバイト列で、
`image.Image` を PNG にする処理は termimg に無い）。

**開発用 CLI**: `tools/` に mermaid ファイルを PNG に変換する小さな CLI を置き、make ターゲットから
使う。実機での確認と E2E に使う。リリースも配布もしない。

### 表示の大きさ

既存の `termimg.BoxFor` は写真向けの方針で、画像を最大 40 桁・画面の高さの 3 分の 1 に収める。
図をこの枠に入れると、1600×1200 の図の文字は約 5.6pt まで縮み、読めない（検証パスの試算）。
そこで図には別の枠の決め方を使う。

段 0 の実測（iTerm2 と kitty、Discussion Log）で決めた枠の決め方:

- **図の文字を端末の文字と同じ大きさに見せる。** 図の文字の高さ（em）を「セルの高さ ÷ 1.2」に
  合わせる。運用者が 0.85・1.00・1.15 倍を見比べ、両端末で 1.00 倍を選んだ。
  - 高さ（行）= 画像の高さ ÷ 図の文字の大きさ(px) ÷ 1.2
  - 幅（桁）= 画像の幅 ÷ 図の文字の大きさ(px) ÷ 1.2 × セルの縦横比（高さ ÷ 幅）
- **幅の上限は端末の幅 − 1。** 超える図は縦横比を保って縮める。文字が小さくなって読みにくいのは
  見た目の問題なので、表示を拒まない（読めなければ運用者がモデルに直すよう伝える）。
- **セルの縦横比は `TIOCGWINSZ` から得る。** これは OS から読むだけで端末への問い合わせではない
  ので、BubbleTea の実行中でも応答が入力欄に漏れない。取れないときは 2.25（termimg の想定値。
  iTerm2 の実測値と一致）を使う。端末への問い合わせ（CSI 16t など）は使わない。
- **高さには見た目の上限を設けない。** 画面より高い画像が下部固定のレイアウトとどう干渉するかは、
  組み込みの ADR で確かめて扱いを決める。
- 枠を決める関数は、組み込み先（termimg の隣）に置く。エンジンは表示の大きさを知らない。

### フォントの指定

`FontSpec{Path, Name, BoldPath, BoldName}`

- `Path` — フォントファイルのパス（.ttf / .otf / .ttc）。
- `Name` — .ttc の中から使う書体を選ぶ名前。name テーブルのフル名（ID 4）と PostScript 名（ID 6）の
  **全言語の値**と、大文字小文字を区別せずに照合する。推奨する指定値は PostScript 名
  （例: `HiraginoSans-W6`）。Font Book は日本語環境では「ヒラギノ角ゴシック W6」のような日本語名を
  出すが、それでも一致する。見つからないときは、そのファイルにある書体名の一覧を付けてエラーにする。
  `sfnt.Name` は言語を選べない（最初のレコードを返す）ので、name テーブルは自前で走査する。
  省略すると先頭の書体。
- `BoldPath` / `BoldName` — 太字（ER の実体名、subgraph の見出しなどに使う）。省略すると本文と同じ書体。

振る舞い:

1. **無い文字** — 次のどちらかに当たる文字を「その書体に無い文字」とする: 字形の番号が 0
   （`GlyphIndex == 0`）、または字形の読み込みに失敗する（`LoadGlyph` のエラー）。読み込みには
   成功しても、特定の文字の描画で失敗する書体が実在する（検証パスの実測で 9 書体）。
   `font.Drawer` の `DrawString` / `MeasureString` は、無い文字を豆腐で描き、失敗を黙って捨てるので
   使わない。文字ごとに書体を選ぶループを自前で書く。
2. **ヒラギノで補う** — 指定した書体に無い文字は、1 文字ずつヒラギノで描く。
3. **それでも無ければエラー** — ラベルから文字が欠けるのは見た目の問題ではなく間違いなので、
   欠けた画像は返さない。呼び出し側はソースを表示する。絵文字（✅ など）もヒラギノに無いので
   この扱いになる。
4. **字形を持たない文字は読み飛ばす** — 異体字セレクタ（U+FE00–FE0F と VS17–256）、ZWJ（U+200D）、
   ZWNJ（U+200C）、ZWSP（U+200B）は描かず、エラーにもしない。どの書体にも無い書式文字（Cf）・既定で
   無視される文字（LRM、word joiner など）も同じ。逆に、字形の番号があってもインクを残さない字形
   （空白を除く。Apple Color Emoji のビットマップは x/image では描けない）は「無い文字」とする。
5. **行の高さ** — その行で使った書体の最大 ascent ＋ 最大 descent。ヒラギノの行送り（1.5em）は使わない。
6. **読めない書体はエラー** — エラーはファイルではなく書体の単位で返す（.ttc は書体ごとに読めたり
   読めなかったりする）。理由（フォントのどの部分が読めないか）を付ける。

フォントを読むのは起動時で、読むのはランタイムの cmd 層。描画の層（view 層）はファイルを開かない
（gem-agent ADR-0089 §5 / ADR-0090 §5）。

### Input / Output

- 入力: mermaid のソース文字列（コードブロックの囲みは含まない）。
- 出力: `*image.RGBA`。白地のカードに描く。端末の背景色は問い合わせない。
- エラーは次の 3 種類で、どれも行番号を持つ。呼び出し側はいずれの場合もソースを表示する。
  種類を分けるのは、既存の表示が扱いを分けているため（gem-agent ADR-0063 §4: 対応していない種類の図は
  黙ってソースのまま、描こうとして失敗した図はソースに注記を 1 行）。
  - **図の種類が未対応** — class、journey、gitGraph など。
  - **構文が未対応** — 対応する種類の図の中の、このエンジンが描かない構文。
  - **構文の誤り** — mermaid として正しくない。
- 資源の上限: 時間とメモリのために上限を置き、超えたら「構文が未対応」と同じ扱いにする。ソース
  5 万文字（mermaid 自身の maxTextSize）、ノードと subgraph 300（subgraph 100）、線と関係 500、
  ER の実体 300・属性は実体ごとに 200、sequence の参加者 300・イベント 2000・枠の入れ子 50、ラベル
  1000 文字、`Scale` 8、1 枚 1200 万画素。PNG の大きさは画素数では守れない（1 画素あたり 0.10〜0.67
  バイト）ので、エンコード後の大きさを呼び出し側が `termimg.MaxBytes`（2MiB）と比べ、超えたらソースを
  表示する。今の `drawImage` は上限を超えた画像を黙って描かないので、図がソースごと画面から消えない
  ようにするのは組み込み側の要件（§4 第 3 段階）。
- 同じ入力と同じフォントからは、常に同じ画像ができる。map の反復順に依存しないことをテストで固定する。

### 第 1 段階で対応する構文

**基準は mermaid 公式ドキュメント**（mermaid.js.org の Flowchart / Sequence diagram /
Entity Relationship Diagram の各ページ）。**参照した版は mermaid 12.0.0（2026-09-10 公開）**。ドキュメントに書かれていない字句の細部（ノード ID に使える文字、線の記号の読み方、subgraph の所属）は、同じ版の `flow.jison` と `flowDb.ts` で確かめ、その旨をテストに書く。
以下は、その仕様の中から、実データ（Discussion Log）と仕様上の基本構文を合わせて選んだもの。
【実】は実データに現れたもの。

**共通**

- front-matter（`---` で囲む）: `title` はカードの見出しとして描く。`config` は無視。
- ラベル内の `<br>` / `<br/>` は改行。`#quot;` などの文字参照と `#35;` のような数値参照は文字に戻す。
- `%%` コメントは無視。

**flowchart / graph**

- 向き: TD / TB / BT / LR / RL
- ノードの形: 旧来の書き方の 14 種すべて（四角、角丸、スタジアム【実】、サブルーチン、円柱【実】、
  円、非対称、ひし形【実】、六角形、平行四辺形【実】、平行四辺形 alt、台形、台形 alt、二重円）
- 引用符付きのラベル `A["…"]`【実】
- ノード ID: 日本語を含む ID、`End` のような大文字の語【実】（予約語は小文字の `end` だけ）
- 線: 実線・点線・太線、矢印なし、長さ違い（`--->` など）、`o` 端・`x` 端、両端（`<-->` `o--o` `x--x`）
- 線のラベル: `-->|文字|`、`-- 文字 -->`【実】、`-. 文字 .->`、`== 文字 ==>`、`-- 文字 ---`
- 連結 `A --> B --> C`、`&` による一括指定【実】
- 閉路【実】
- subgraph（1 段）【実】。`subgraph id [タイトル]`、`subgraph id["タイトル"]`、
  `subgraph タイトル`、日本語の ID【実】。subgraph を端点とする線【実】
- **subgraph の所属規則** — ノードは、それに**最初に言及した subgraph** に属する。トップレベルで
  宣言しただけでは所属は決まらない。mermaid.js（flowDb の `makeUniq`）と同じ規則。実データの応答で
  subgraph を使う 11 個中 6 個で結果が変わり、規則を誤るとノードが別の箱に入った誤った図になる。

**sequenceDiagram**

- participant / actor、`as` による別名【実】
- メッセージ: `->` `-->` `->>` `-->>` `-x` `--x` `-)` `--)` と双方向の `<<->>` `<<-->>`
- 自分自身へのメッセージ【実】
- autonumber【実】（開始値・増分つきも）
- activate / deactivate、`+` / `-` の書き方【実】
- note（left of / right of / over）【実】
- alt / else / loop / opt / par / and / critical / option / break の枠
- box（参加者のまとまり）
- `rect` は色の指定なので枠だけ無視し、中身は描く

**erDiagram**

- 実体、別名、ハイフンを含む名前・引用符付きの名前
- 属性ブロックの無い実体【実】
- 属性（型・名前・PK / FK / UK とその組み合わせ・コメント）【実】、省略可能な型 `string?`、
  `~` による総称型（`List~int~` は `List<int>` と表示）
- 多重度の全記号と、語による書き方（`one or more` など）。記号はどちら側にも書ける（`o{--||`）
- 識別関係（`--`）と非識別関係（`..`）、関係のラベル（引用符付きを含む）【実】
- `direction`（flowchart と同じ配置を使うので対応する）

**無視するもの（見た目だけの指定）**: classDef、style、class、`:::`、linkStyle、`%%{init}%%`、
click、subgraph の中の `direction`、`~~~`（見えない線。配置のためだけのもの）、accTitle / accDescr。

**未対応とするもの（構文が未対応のエラー）**: 入れ子の subgraph（第 2 段階）、`A@{ shape: … }` の
拡張形状、edge ID（`e1@-->`）、Markdown 文字列（`` "`…`" ``）、sequence の create / destroy と
半矢印・中央接続、ER の subgraph、上に挙げたもの以外の読めない行すべて。

### 第 2 段階で対応する構文

基準は第 1 段階と同じ mermaid 12.0.0。mermaid 11 以降、pie などの文法は jison ではなく Langium
（`packages/parser/src/language/*/*.langium`）で書かれているので、それを字句の規則として移植する。

**pie**（`pie.langium`・`common.langium`・`pieDb.ts`・`pieRenderer.ts`）

- 見出し行 `pie`、続けて任意で `showData`。どちらも後ろに空白・行末・`%%` 以外が続けば構文の誤り
  （Langium のキーワード規則）。`title`・`accTitle`・`accDescr`（`{ … }` の複数行も）は見出しと同じ行にも
  書ける。`title` は見出しとして描き、`accTitle` / `accDescr` は無視。
- 行 `"ラベル" : 数`。ラベルは `"…"` か `'…'` で、`\` によるエスケープを Langium の規則で戻す。数は
  `-?[0-9]+\.[0-9]+` か `-?(0|[1-9][0-9]*)`（その後に `.` が続かない）。それ以外の書き方は構文の誤り。
- 負の値は誤り（pieDb）。同じラベルの 2 回目以降は無視（最初の値を使う）。
- 描くもの（pieRenderer）: 扇形は書いた順に 12 時から時計回り。全体の 1% 未満の項目は扇形を描かず、
  扇形の角度は描く項目だけの合計で決める。扇形の中の % は**全体の合計**に対する割合を
  `toFixed(0)` で丸めたもの。凡例はすべての項目を書いた順に並べ、`showData` のときは `ラベル [値]`
  （値は JavaScript の数の文字列化）。色は 12 色を項目の順に割り当てて繰り返す（色の値はこのエンジンの
  白地カードに合わせて選ぶ）。
- **このエンジンで決めること**: 細い扇形の % は本家では隣と重なって読めなくなる。ここでは文字の重なりを
  間違いとして扱う。すべての項目の % を凡例の右の列に右揃えで書き（扇形のない項目は `<1%`、合計が 0 なら
  書かない）、扇形の中には文字が収まるときだけ書く（2026-09-29 の運用者の判断。Discussion Log）。
- 上限: 項目 100。値の合計が有限でなければ未対応の構文。

**stateDiagram / stateDiagram-v2**（`stateDiagram.jison`、`stateDb.ts`、`dataFetcher.ts`、
`stateCommon.ts`。2 つの見出しは同じ図 — `stateDetector-V2.ts`）

- **読み方。** 字句規則は ER と同じく順番どおりに移す: 最初に当たった規則が勝ち、大文字小文字を区別せず、
  単語の文字で終わる規則には `\b` が付き、字句解析の状態（`STATE`、複合状態の中身の `struct`、`NOTE`
  など）も文法どおり。mermaid は原文の末尾に改行を 1 つ足して読む（`Diagram.fromText`）。mermaid と
  共通の帰結:
  - 見出しは `stateDiagram` か `stateDiagram-v2`（書いたとおり: 判定は大文字小文字を区別する）の後に空白。
    見出しだけなら空の図。
  - 状態の id（`ID`）は `:`・`-`・`{`・空白以外の文字の並び — `;` と `}` も含み、日本語の id も id。行中の
    `%%` で切れる。`state ` の後の名前は空白か `{` まで（`-` と `:` も入る）、`as` の後は行末か `{` まで
    （空白も入る）。`[*]` は開始か終了。空白が続く `note` と `state` は常にキーワード。
  - `direction TB|BT|LR|RL`（大文字小文字を問わず、語の中でも: `mydirection lrx`）を含む行は、字句解析の
    位置から行末までが方向の文になる。最上位ではこの規則がコメント・`state`・`note`・見出しより先、
    複合状態の中では `note` より先。逃れるのは複数行の注記の本文だけ。`\s+` は改行もまたぐので、行末の
    `direction` と次の行頭の `LR` は 1 つになる。`direction TD` は方向ではなく 2 つの状態。
  - `click`・`href`・`default`・`hide empty description`・`scale`・`accTitle`・`accDescr` がキーワードで、
    `"…"` が字句になるのは最上位だけ。最上位の `default` という名前の状態は構文エラー、複合状態の中の
    `hide empty description` は 3 つの状態。
  - 説明と遷移のラベルは `:` の後から行末・`;`・`::` まで（先頭の `::` は残る: `A :: y` の説明は `: y`）。
    中の `%%` は残る。後もそのまま字句解析が続き、`A : x; y` は状態 `;` と `y` も作る。
  - 複合状態の外では改行が字句になるが、中ではならないので、中では文が次の行へ続く（`A` の次の行の
    `: x` は A の説明になる）。
  - `{` の前に ASCII の語が 2 つある `state` は mermaid のエラー（"State name must be a single word"）で、
    改行をまたいでも当たる（`state a` の次の行が `state b {`）。ASCII 以外の語は数えない
    （`state 状態 X {` は X を作る）。
- **文。** `id`、`id : 説明`、`a --> b` と `a --> b : ラベル`、`state "説明" as id`、`state id { … }` と
  `state "説明" as id { … }`（複合状態。20 段まで入れ子にできる。最上位では `{` を次の行に書いてもよい）、
  `state id <<fork>>`・`<<join>>`・`<<choice>>` と `[[fork]]` の形（id は印の前すべて:
  `state my fork <<fork>>` は `my fork`）、複合状態の中の `--`（並行する領域）、`note left of id : 本文`
  （本文は `:`・`;`・行末で切れる）、`note right of id` … `end note`、`direction`。形だけ確かめて捨てるもの:
  `classDef`（`classDef default` は mermaid のエラー）、`class`、`style`、`:::`、`click`、
  `hide empty description`、`scale N width`、`accTitle`、`accDescr`。浮いた注記（`note "本文" as N`）は
  読むが描かない（mermaid も何も残さない）。`state id` だけの行は何も宣言しない（mermaid の文法は字句を
  残し状態を作らない）。
- **意味**（stateDb の `docTranslator`、`dataFetcher`）:
  - `[*]` は遷移の最初（か単独）ならその範囲の開始、2 番目なら終了。範囲（最上位・各複合状態・
    各並行領域）ごとに開始と終了は 1 つずつで、その中のすべての `[*]` が共有する。
  - 状態は図全体で id ごとに 1 つ。状態は、それに触れた**最後の**複合状態（読む順、深さ優先）に属し、
    最上位での言及は数えない（`Object.assign` が最後の `parentId` を残す）。
  - 状態の種類（fork・join・choice・開始・終了）は最初の言及で決まる。説明が付くと、どれも普通の状態に
    なる（`dataFetcher` の形の決め方）。注記の文には型が無い: 注記で初めて出た状態は形を持たず、後に説明が
    無ければ mermaid は描けない（"No such shape"、`nodes.ts`）。注記の左右は書いたままの `left of` と
    比べるので、`NOTE LEFT OF` は右の注記。
  - 説明は積み重なる: 無ければ id を表示、1 つ目がラベル、2 つ以上なら 1 つ目を見出し、残りをその下の
    行にした状態になる。説明が 2 つ以上ある複合状態は mermaid のエラー。`state "説明" as id:追加`
    （id にコロン）は未対応。
  - `--` は複合状態を領域に分け、各領域はそれぞれ開始と終了を持つ範囲になる。先頭や連続の `--` は空の
    領域を作り、末尾の `--` は複合状態を分けずに余分な仕切りの形を残す。3 つとも未対応。
  - 方向: 範囲は自分の文の中の最後の `direction` を取り、無ければ TB。入れ子の範囲は親の方向を
    引き継がない（`DEFAULT_NESTED_DOC_DIR`）。領域に分かれた複合状態の文書には領域しか無いので、そこに
    書いた `direction` はそれが書かれた領域に効く。
  - ラベルは HTML（`getEffectiveHtmlLabels` の既定は true）。説明・遷移のラベル・複合状態の見出し・注記・
    ラベルとして出る id は markdown（`markdownToHTML`）: 書式は ER と同じく拒み、`<br>` と改行
    （`state "a⏎b"` の改行も）で行を分け、各行の前後の空白を除き空白の連続を 1 つにし、空行は表示されない。
    見出しと行を持つ状態は markdown を通さずに描かれる（`createLabel`、rectWithTitle）: `**x**` は
    書いたまま、書かれた `\n` で改行。`<br>` 以外の HTML はどこでも拒む。1 行の注記は id の後の 2 文字
    （空白とコロンを含む）を失う（`yytext.substr(2)`）— mermaid と同じ。
- **このエンジンで決めること**（2026-09-29 の運用者の判断: 複合状態は内側を先に配置する）:
  - 範囲ごとに flowchart の配置で、その範囲の方向に並べる。複合状態は親の範囲のノードで、見出しの帯と、
    方向を横切る向きに並べた領域（間は破線）が入る大きさ。複合状態への遷移・複合状態からの遷移は枠で
    止まる。
  - 両端が別の範囲にある遷移（外から複合状態の内側の状態へ、領域どうし、複合状態とその内側の状態）は
    この方式では描けないので未対応。自分自身の内側にある状態も未対応。
  - 注記は書いた側に置き、矢印の無い点線で状態とつなぐ（2026-09-29 の運用者の確認: `dataFetcher` の注記の
    辺の向きに従うと、TB では右の注記が状態の下に来ていた）。TB と BT では状態の横に置く: 状態と、両側に
    広い方の幅の枠を合わせて 1 つのノードにし、遷移が着く状態を真ん中に、状態は注記の高さまで伸ばす。
    同じ側の注記は縦に積む。LR と RL では、どの状態でも注記をノードにし、その側に来る向きの点線でつなぐ。
    TB と BT では開始・終了・choice・fork・join は伸ばせず、自分への遷移がある状態はノードの横からループが
    出るので、それらへの注記は書いた側に置けない: 未対応。注記は状態の範囲に属する（mermaid は注記を最上位に
    付ける）。
  - `root` という名前の状態は未対応: `dataFetcher` はその id の状態を作らず、その名前の複合状態の中身を
    最上位に置く。そこへの遷移は行き先が無い。
  - 形: 状態は角の丸い四角（見出しがあれば下に罫線）、開始は塗った円、終了は塗った円を囲む輪、choice は
    小さなひし形、fork と join は範囲の方向を横切る棒、複合状態は角の丸い枠で上の帯の中央に見出し。
  - 上限: 状態・注記・複合状態を合わせて flowchart のノードと同じ 300、遷移はリンクと同じ 500、複合状態
    100、入れ子 20 段。

**gantt**（`gantt.jison`、`ganttDb.js`、`ganttRenderer.js`。dayjs 1.11.21 と customParseFormat・isoWeek・
advancedFormat、時間軸・目盛り・`timeFormat` は d3 7.9.0）

- **読み方。** 字句規則は ER・state と同じく順番どおりに移す（先勝ち、大文字小文字を区別しない、単語の文字で
  終わる規則に `\b`）。mermaid と共通の帰結: 字句の始まりのキーワードはタスク名に勝つ（`call mom : 1d` は
  エラー）。日付で始まる行（`2026-01-01 kickoff : …`）はエラー、文字と `%` で始まる行はコメントとして
  読み飛ばす。`section` や `title` だけの行は次の行を呑み込む。`dateFormat`・`axisFormat`・`tickInterval`・
  `includes`・`excludes` の値は `#`・`;`・行末まで、末尾の空白も残る（`tickInterval 1day ` は無視される）。
  `#` や `;` の後もそのまま字句解析が続く — タスク名になり、たいていはエラー。
- **文。** `title`、`dateFormat`（無ければ開始はすべてブラウザの `Date` で読み、終わりの日付は読まれない —
  文書の「既定 `YYYY-MM-DD`」はコードと違う）、`axisFormat`（既定 `%Y-%m-%d`、`dateFormat` がちょうど `D`
  なら `%d`）、`tickInterval`（`^[1-9]\d*(millisecond|second|minute|hour|day|week|month)$`、それ以外は無視）、
  `excludes` と `includes`（小文字にし空白とカンマで分けた語を積み重ねる）、`weekday`（`week` の目盛り間隔の
  週の始まりにだけ効く）、`weekend friday|saturday`、`inclusiveEndDates`、`section`、タスク `名前 : データ`。
  `topAxis` は mermaid 12.0.0 のエラー（文法が ganttDb に無い `yy.TopAxis` を呼ぶ）。読んで捨てるもの:
  `todayMarker`、`click` / `href` / `call`、`accTitle`、`accDescr`。
- **タスク**（ganttDb）: 先頭のタグ `active`・`done`・`crit`・`milestone`・`vert`（書いたとおり、大文字小文字を
  区別）、続いて 1〜3 項目 — 終わり、開始と終わり、id と開始と終わり。タグだけ、3 項目を超えるものは mermaid
  が落ちる。開始は `dateFormat` の日付、`after id…`（小文字。id は ASCII の `[\d\w- ]`、空白 1 つで分ける）、
  `x` か `X` なら数字の並びをミリ秒として（`X` でも — 終わりの `X` は秒）、または 1 項目なら前のタスクの
  終わり（id で引く: その id の最後のタスク、`vert` も数える）。終わりは `dateFormat` の日付
  （`inclusiveEndDates` なら 1 日後）、`until id…`、期間 `N(ms|s|m|h|d|w|M|y)` — 日と週の小数は日に丸め、
  月と年の小数は切り捨て、月末は詰める。それ以外なら開始と同じ時刻で終わる。`after` は挙げたタスクの
  最も遅い終わり、`until` は最も早い開始を、ganttDb の比べ方で取る: まだ置かれていないタスクは時刻を持たず
  比較が偽になり、最初に挙げたものが残るので、id の順で答えが変わる。ganttDb は最大 11 回まで繰り返し、
  すべて置けた時点で止まる。除外日（`weekend` に従う `weekends`、曜日名、`dateFormat` か `YYYY-MM-DD` で書いた
  日付、`includes` のものを除く）は開始の翌日から数え、終わりを `YYYY-MM-DD` の日付で書いたタスク
  （`dateFormat` にかかわらず字面で判定）以外の終わりを後ろへ延ばす。棒は延ばす前の終わりまで。行は原文の
  順のタスク、`vert` は行を取らない。同じ id は最後のもの。
- **日付**は dayjs の厳密な読み取りに従う: 書式の字句（`YYYY YY Y Q M MM MMM MMMM D DD Do H HH h hh m mm s
  ss S SS SSS A a Z ZZ`、`[文字]`）で読み、書式で書き戻した結果が入力と一致すること — なので `S`・`SS`・
  `Y`・週と `L…` の字句は決して読めず、`Z` は `+00:00` のときだけ、`D` は `05` を読めない。年が無ければ
  今日の年。月が無ければ、年があれば 1 月、無ければ今月。日が無ければ、年か月があれば 1 日、無ければ今日。
- **このエンジンで決めること** — 出力は描いた日にもブラウザにも依存しない:
  - 時刻は UTC に設定したブラウザと同じに計算する（夏時間なし）。
  - 未対応: どのタスクも指さない `after` / `until`（mermaid では今日）。置けないタスク（循環）。dayjs が
    読めない開始 — mermaid はブラウザ自身の `Date` に渡し、ブラウザごとに違う — ただし ECMAScript の
    日時文字列形式（`YYYY`、`YYYY-MM`、`YYYY-MM-DD`、`THH:mm[:ss[.sss]]` と `Z` / `±HH:mm`）はどれでも同じに
    読むので受け付ける。月か日はあるのに年が無い `dateFormat`。時刻だけの `dateFormat` は、日付がどこにも
    現れないときだけ受け付ける: `excludes`・`includes` が無く、月・年の期間が無く、軸の書式が
    `%H %I %M %S %L %f %p %X` だけを印字し、日付で位置が決まる目盛り間隔が無く（`week`、`month`、2 以上の
    `day` — d3 は日にちで絞る — 、1 日を割り切らない `millisecond` — エポックから数える）、図の期間が 2 日未満
    （このとき d3 は時間以下の目盛りを選ぶ）。ほかに未対応: 開始より前に終わるタスク（mermaid の棒は幅が負で
    描かれない。`dateFormat X` は開始をミリ秒、終わりを秒で読むので起きやすい）、`excludes` と照らす日が
    20 万日を超えるもの（上限: ganttDb は 1 日ずつ歩く）、1 万を超える `week` の目盛り間隔（d3 は 1 週ずつ歩く）。
  - 開始の無い最初のタスク、タグだけ、3 項目を超えるものは mermaid が落ちる: エラー。
  - 今日の線は描かない。`displayMode: compact` と設定の `topAxis`（front matter）は見た目の指定として
    無視する: タスクはすべて自分の行、軸は下に 1 本。
  - 配置: 左の列に節の見出し、列の左右中央かつその節の行の並びの中央に（同じ節が離れて繰り返すと、それぞれの並びに見出しを
    付ける — mermaid はまとめて位置がずれる）。節の帯の上にタスクごとの行。時間軸は最も早い開始から最も
    遅い終わりまで。棒はその尺度で、マイルストーンは開始に長さの半分を足した位置のひし形。タスク名は棒に
    収まれば中、収まらなければ右（絵が広がる。mermaid は端で左に回し、節の見出しに重なる）。除外日は期間が
    満 5 年以内なら網掛け — すべての並びを。mermaid は最後の日まで続く並びを落とす。`vert` は行を貫く線で、
    文字は軸の下に重ならない段に分けて置く。目盛りは d3 の時間軸のとおり（既定 10 本。`tickInterval` は
    10,000 本を超えないとき、超えるなら既定。描くのは 20,000 本まで）、ラベルは `axisFormat`（d3-time-format の指定子、英語）。
  - 時間軸の幅はこのエンジンのもの: 軸のラベルを間を空けて並べられる幅、最小 36 em — mermaid は置き場所の
    幅いっぱい。120 em を超える（目盛りが密、たとえば何か月にわたる `tickInterval 1day`）なら、収まる最小の
    k で k 本おきにラベルを付け、目盛りの線はすべて描く。mermaid はすべてのラベルを重ねて描く。
  - 文字は SVG の text と同じに描く: タスク名は書いたとおり（`<br>` も）前後の空白を除いて、節の見出しは
    `<br>` で改行、文字参照は戻す。
  - 上限: タスク 500（flowchart の線と同じ）。

**mindmap**（`mindmap.jison`、`mindmapDb.ts`、`mindmapRenderer.ts`。ラベルは `rendering-util/createText.ts` と
`handle-markdown-text.ts`。左右への振り分けは `mermaid-layout-tidy-tree` の tidy-tree 配置）

- **読み取り。** 字句規則は ER・state・gantt と同じく順番ごと移植する（先勝ち、大文字小文字を区別しない、
  単語文字で終わる規則には `\b`、排他的な状態 `NODE`・`NSTR`・`NSTR2`・`ICON`・`CLASS`）。mermaid が足す
  行末も足す。見出しは `mindmap`（検出は大文字小文字を区別する。字句の `mindmap` は区別しないので、文字が
  単語 `mindmap` で始まるノードは大小を問わず mermaid の構文エラー。`mindmaps` は違う）。ソースは mermaid
  自身の下ごしらえの後で読む: 指令は `directiveRegex` が見つける所で除き（`%%{` の後に語が要るので
  `%%{}%%` は文字。`}%%` が無ければ文の終わりまで）、行全体のコメントはその直前の空白だけの行ごと除き
  （`cleanupComments`。行末の無い最後のコメント行は、その前の行末を残す）、行末を 1 つ足す。ノードは見出しと同じ行にも書け（`mindmap root`）、
  そのとき字下げは `mindmap` の後の空白。mermaid と同じになる帰結:
  - ノードは行の文字。字下げは前にある JavaScript の空白文字の数（タブ・U+3000・U+00A0 もそれぞれ 1）。
    文字は、囲みの無い文字（`[^([\n){}]+`、id とラベルを兼ねる）か、省略できる id と囲んだラベル。囲みの
    無い文字は最初の `(`・`[`・`)`・`{`・`}` で終わるので、`言語 (Go)` はラベル `Go` の角丸ノードになり、
    囲んだラベルの後ろに `%%` のコメント以外があれば構文エラー。囲みの無い文字の中の `:::` と `%%` は文字
    （`A:::x` はノード `A:::x`、`A %% c` はノード `A %% c`）。
  - 形は開きの囲みだけで決まる（`getType`）: `[` 四角、`(` は `)` で閉じれば角丸・それ以外は雲、`((` 円、
    `)` 雲、`))` 爆発、`{{` 六角形。`(-` と `-)` は既定の形を開くが、id や文字が `-` を取り込まない所に
    限る（`x(-y-)` のラベルは `y-`、`a-)x)` はノード `a-` の雲でラベル `x`）。ラベルは開きが何であれ最初の
    `)`・`]`・`}}`・`(`・`((` で終わる（`{{h]` はラベル `h` の六角形）。中のどこかにある `}` 単独、`{x}`、空の
    ラベルは構文エラー。`"…"` と `` "`…`" `` は囲みのすぐ内側にあるときだけラベルを引用する（`a[ "x"]` は
    引用符ごと見え、`a["x" ]` はエラー）。逆引用の形は `"` と逆引用符を含められない。ラベルは行をまたげる。
  - `:::` とクラスの行、`::icon(…)` の行（アイコンの文字は行をまたげる）は直前のノードを飾る。ノードより
    前にあると mermaid は落ちる。ここではエラー。
  - 空行・空白だけの行・コメント行は何も区切らない。
- **木**（`MindmapDB.addNode`）: 最初のノードが根。その字下げを基準とし、ノードの深さは字下げから基準を
  引いたもの。親は、それより前で深さがより小さい最後のノード — なので、前の 2 つの深さの間に字下げした
  ノード（文書の「あいまいな字下げ」）は、近いほうの浅いノードにつく。後のノードが根と同じか浅い深さなら
  mermaid のエラー（"There can be only one root"）。ノードが 1 つも無い（`mindmap` の後に空行）なら空の図、
  `mindmap` だけなら mermaid の構文エラー。
- **ラベル。** ラベルはすべて markdown（mermaid 12.0.0 は全ノードに `labelType: 'markdown'` を与える）かつ
  HTML（`htmlLabels` の既定は true）で、`markdownToHTML` で描かれる。これは強調（`strong`・`em`）だけを書式
  として描き、他の markdown の字句は書いたとおりに見せる。したがって:
  - 強調は未対応（2026-09-29 の運用者の判断: ER・state と同じ）。CommonMark が区切りの並びを読むとおりに
    見つける — 開ける `*` か `_` の並びの後に、同じ文字で閉じられる並びがあれば強調 — 迷えば拒む側に倒す:
    `_snake_case_` と `__init_db__` は強調、`user_id` は違う（ER が使っていた正規表現は範囲の中の `_` を
    見落とした。ER と state も同じ判定に替えた）。読み方が分かれる所では、どれか 1 つでも強調と読めば
    拒む: 空白を Go として・JavaScript として読む（U+0085・U+FEFF）、`_` を CommonMark の規則で・marked の
    規則で読む（marked は文字か数字の隣だけを拒むので、結合文字やゼロ幅空白の後の `_` は開ける）、タグを
    文字で覆う、コードやオートリンクの直後の区切りを先頭として読む。ラベルに `<` があると DOMPurify が
    markdown より先に文字参照を戻して書き戻す（`&`・`<`・`>`・U+00A0 は参照に）ので、`#42;x#42;<br>y` も
    強調で、書き戻した形も確かめる。1 行の見出し・リスト・引用・コードは、mermaid と同じく
    書いたとおりに描く。
  - 行をまたぐラベルは行末ごとに改行し、各行の前後の空白を除く。空の行は出ない。行をまたぐラベルで、
    markdown のブロックを始める行（リスト・見出し・引用・コードの囲み・HTML・字下げのコード・`---` /
    `===` の下線・表の区切り行）、強制改行（空白 2 つかバックスラッシュで終わる行）、行末をまたぎうる
    コード・リンク・取り消し線があれば未対応（改行するのは段落の行末だけ）: mermaid は生の文字を、行末を
    空白にして見せる。そのままにするもの: ブロックで始まり Unicode の空白で終わるラベルは、mermaid では
    空に見える行が 1 つ増える（空白が段落になる）。文字は変わらない。
  - ASCII の記号の前のバックスラッシュ（markdown のエスケープ。mermaid は落とす）は未対応。文字の中に
    書いたアイコン（`fa:fa-car`。mermaid はアイコンに置き換える）と数式（`$$…$$`。KaTeX で描く）も未対応。
  - `<br>`（と `</br>`）は改行。文字・`/`・`!`・`?` の前の `<` は未対応（タグを開き、残りが見えなくなる:
    `x<y` は `x` と見える）。文字参照と HTML の参照は戻す（`#35;`、`&amp;`）。HTML が知らない名前は参照の
    まま見える（`#foo;` は `&foo;`）。続く空白は 1 つに見せる（mermaid は `break-spaces` で折り返した
    ラベルでは残す: 文字ではない）。`;` の無い数値の参照（`&#1`。ブラウザは読む）は未対応。ラベルは
    flowchart と同じく 1000 文字まで。
  - **折り返し**: mermaid はラベルをある幅まで伸ばし、そこで折り返す（`addHtmlSpan`: その幅の箱で
    `white-space: break-spaces`、行は中央揃え）。16 px の文字で、既定の形・円・雲・爆発は 200 px
    （`maxNodeWidth`）、四角・角丸・六角形は 120 px（描画側が幅を 0 にするので `flowchart.wrappingWidth`）。
    ここでは 12.5 em（その 3 つの形では 7.5 em）を超える行を折り返す: 空白で、語の中のハイフンの後で
    （数字の前は除く）、また前後どちらかが CJK（漢字・かな・全角形）の文字の間で。ただし閉じの約物
    （`、。，．）」』】〉》〕｝！？ー` と小書きのかな）の前と開き括弧の後では折らない。折れ目の無い、
    幅を超える並びは、mermaid と同じくその行に置いたまま、ノードを広げる。
- **読んで捨てる**: `:::` のクラス（flowchart と同じくサイトのスタイルシート用）と `::icon(…)`（ページが
  アイコンフォントを用意したときだけ描かれる。2026-09-29 の運用者の判断）。front matter の `config` は
  `layout: tidy-tree` も含め無視する。
- **ここで決めること** — mermaid は結果の決まらない物理シミュレーション（`cose-bilkent`）で配置する。ここ
  では決まった規則で並べ、大筋は mermaid 自身の `tidy-tree` 設定と同じ形にする: どれがどれの子かは同じ、
  位置は違う。
  - **左右**: 根の子を交互に振り分ける。1 番目は左、2 番目は右、…（`convertToDualTreeFormat`）。各側は根から
    外へ伸び、1 段目の並びは根の高さを中心にそろえる。
  - **帯**: 部分木はそれぞれ自分だけの横の帯を持つ。兄弟の帯はソースの順に上から下へ、隙間を空けて積む。
    親は子の脇に、最初と最後の子の中央の間の真ん中に置き、子は親の外側の辺から隙間 1 つ外に立つ（右側は
    そこで左揃え、左側は右揃え）。なので帯の中には自分の部分木しか無く、親と子の間には線しか無い。
  - **線**: 親の外側の辺の中央から子の内側の辺の中央へ、なめらかな曲線（両端で水平）をノードの下に描く。
    太さは木の深さとともに細く（mermaid の `edge-depth-N` は深さでなく字下げの文字数で数える）、色は子の
    系統の色。
  - **形**: 既定は角丸の四角、`[ ]` 四角、`( )` 角の丸みの大きい四角、`(( ))` ラベルを囲む円、`) (` 雲、
    `)) ((` 爆発、`{{ }}` 六角形。どれも系統の色で塗り、ラベルは中に。
  - **色**: 根は専用の色。根の子がそれぞれ系統を始め、`i` 番目は色 `i mod 11`（mermaid の
    `MAX_SECTIONS - 1`）、子孫はそれを受け継ぐ。11 色は白地のカード向けに、どの 2 色も似ないよう選び（円グラフの最初の 10 色と藍色: 2026-09-30 の
    運用者の判断。円グラフの 11 色目は 5 色目とほぼ同じ青緑）、文字は読めるほうの濃色か白。
  - 上限: ノード 300（flowchart と同じ）。
- **描くたびに確かめること**: すべてのノードが 1 度ずつ絵の中に置かれ、形どうしが重ならない。ラベルが形の
  中にある（厳密に: 雲や爆発の辺が文字の箱に入らない）。子は親の外側に隙間 1 つ離れて立ち、兄弟はソースの順。帯には自分の部分木しか無い。線は 2 つの
  ノードの辺で始まり・終わり、その間にとどまる。折り返した行はどれも形の幅以内か折れ目の無い並びで、折り返しで
  文字が失われていない。

### 配置の仕様

- **flowchart と ER**: ノードを段に分けて並べる方式（Sugiyama 法）を自前で書く。
  1. 閉路の除去: 深さ優先探索で見つかった後ろ向きの線を反転して扱い、描くときに向きを戻す。
  2. 段の割り当て: 最長経路法。
  3. 2 段以上をまたぐ線には、各段に中継点を置く。線のラベルも中継点として 1 段を占める。
  4. 交差を減らす並べ替え: 重心法を上下に繰り返す。同じ順位はソースに現れた順で決め、結果を
     決定的にする。
  5. 座標: 段の中で左から詰め、中継点の列はまっすぐにする。1 本の線から枝分かれするノード
     （合流するノード）は、その 1 本の列に揃える。ある面に線が 1 本だけのノードは、その線の列の
     中央に置く（ひし形なら頂点で線を受ける）。1 対 1 の線でつながる並び（段ごとに 1 つずつ）は、
     全員が届く 1 本の列にまとめて揃える。subgraph を端とする線は枠の中央を狙い、枠どうしを
     結ぶ線でつながる subgraph は中央で揃う。
  6. 線は段の中をまっすぐ縦に通り、段と段の間では「縦・横・縦」の直角の折れ線で列を移る。
     横の部分には隙間の中で線ごとの高さ（トラック）を割り当てるので、線どうしは直角にしか
     交わらない。トラックどうしは 0.8em 離す。2 本の線が互いに相手の列へ移る場合は、片方が空いた
     列を経由する回り道をする。横の部分が別の線の出ていく列を越えるならその線より下で、入ってくる
     列を越えるなら上で曲がる（1 つのノードから扇状に出る線どうしが交わらない）。矢印の手前には
     矢印より長いまっすぐな部分を残す（段の順に逆らう線でも）。列を移る線は、できるだけノードの
     すぐ脇で移る。扇状に出る線を 1 本だけ受けるノードには、その中央で入る（すでにまっすぐな線は
     そのまま）。
     端点はできるだけ、線が向かう列の真上（真下）に置く。
  7. 同じ組の間の複数の線は、面ごとに 0.8em 以上離れた別の端点を持つ。面が足りなければノードや
     枠を大きくする（自分自身への線の端も含め、実際の外形の上で距離を測って確かめる）。自分自身
     への線はノードの脇にループを描き、外側のループは内側のラベルより外から出る。
  8. subgraph: 所属するノードを段の中で隣り合わせに保ち、囲む枠と見出しを描く。subgraph を端点と
     する線は枠の縁で止める。
  9. 向き: TD で配置し、LR / RL / BT は座標を変換して得る。
- **state**: 範囲（最上位・各複合状態・各並行領域）ごとに上の flowchart の配置で並べる。内側から先に
  配置し、複合状態は内側を配置した大きさのノードとして親の配置に入り、内側はその箱の中へ移す。
- **mindmap**: 根の左右に、帯に分けた木（上記）。
- **sequence**: 参加者を横に並べ、メッセージを縦に積む。自分自身へのメッセージは右に折り返す。

### 罫線表示（第 2 段階 2e）

画像を描けない端末では、図を罫線の文字で描く。今は gem-agent が `mermaid-ascii`（コミュニティ製）で描き、
mermaid をその文法へ書き換える表と 2 つの確かめ（書いたラベルがすべてある、線 1 本に矢印 1 つ）を前後に
挟んでいる。これをこのエンジンに置き換える（2026-09-30 の運用者の判断）:

- **範囲**: flowchart / graph・sequenceDiagram・erDiagram — 今の罫線表示が描く 3 種。円グラフ・状態遷移図・
  ガント・マインドマップは、そうした端末では今どおりソース。罫線は TUI だけ（gem-agent の素の REPL や
  `-p` の出力には描かない）。そうした端末でソースを見せている lagent にも同じ罫線表示を入れる。
- **API**: `raster.RenderText(d Diagram, opts raster.TextOptions) (string, error)` と
  `raster.RenderTextSource(src, opts)` — 罫線が走らせる層の配置を持つ raster パッケージに置く。図のデータは絵と同じ `Parse` のものなので、罫線が絵と違う読み方をする
  ことはもう無い（mermaid-ascii は BT を TD、RL を LR で描き、`Z --> S` で幻のノードを描き、`<br>` と
  ASCII 以外の sequence を拒んでいた: 実測）。エラーは同じ 3 種と `LayoutFault`。呼び出し側はどれでも
  ソースを見せる。
- **文字の幅**: `TextOptions.Width func(r rune) int` が文字の占める桁数を返す。呼び出し側は自分の端末処理と
  同じ測り方を渡す。1 文字（rune）が書記素クラスタ 1 つになるよう、複数の rune からなるクラスタ（結合文字・
  ZWJ・異体字セレクタ・地域指示子・絵文字の修飾子）を含むラベルは罫線では未対応。既定は Unicode の
  East Asian Width（`golang.org/x/text/width`。`x/image` を通じて既に要求しており、go.mod の行は直接の
  依存になる）: 全角・幅広は 2、他は 1。どの文字のラベルも描く（sequence も）。ラベルの制御文字（C0・C1・
  DEL — 戻した `#27;` は本物の ESC — 、TAB、双方向の制御文字）は罫線では未対応。下の文字はどれも East Asian
  の曖昧幅か中立（x/text 0.42）: 曖昧幅の文字を 2 桁で描く設定の端末では罫線がずれる。問い合わせなしには
  分からないので、今と同じく明記した制約とする。
- **文字**（今の罫線表示にあるものはそれに合わせる）: 箱は `┌─┐│└┘`。ノードの角が形の系統を示す —
  角丸・スタジアム・円・二重円は `╭╮╰╯`、ひし形・六角形（判断）は `◇`、他は `┌┐└┘`。線は `─│` と角、
  点線は `┄┆`、太線は `━┃`、矢印は `►◄▲▼`、端の `○` と `×`。線は交わる（`┼`。点線・太線の交わりは
  その文字があればそれで）だけで、合流しない。矢印はまっすぐな区間の端に付く。subgraph の枠は二重線
  `╔═╗║╚╝`（ノードの箱は一重）、見出しは絵と同じく枠の中、所属するノードの上の行に、横切る線を避けて
  横にずらして置く。それで入らなければノードの下に置く。ER の
  エンティティは表 — 名前、属性ごとに 1 行で絵と同じ列（型・名前・キー・コメント。折り返さない）— 、多重度は
  表の隣の 2 桁に mermaid 自身の記法で（`||`・`|o`・`}|`・`}o`。左側では左右反転）、非識別の関係は点線。
  sequence: 参加者の箱を上と下に（mermaid の `mirrorActors`）、`actor` は参加者と同じ、`│` の生存線、`┃` の
  活性化、メッセージは上に文字を載せた矢印（破線の種類は `┈`。矢印は `►` / `◄`、× の種類は `×`、非同期の
  種類は `)`、`->` / `-->` は無し、`<<->>` は両端）、自分へのメッセージは右へのループ、autonumber は `1.` の
  前置き、注記は箱、`box` のまとまりは見出し付きの枠、枠は種類とラベル付きで、区切りは `else` / `and` /
  `option` を書いた `┈` の線、入れ子は 1 段ごとに 1 桁内側。ブロックの枠は中身（メッセージの文字・注記・内側の
  枠・ラベル）に合わせて広げる。`box` のまとまりは背景の枠で、矢印や文字が横切る。どのセルも「何が何を覆って
  よいか」を知る 1 つの門を通して書く（文字は生存線を覆ってよい、矢印は生存線やまとまりの辺を `┼` で横切る、
  ブロックの枠は何も覆えない）: これが sequence の確かめ。実データの sequence 10 個と乱数 4,000 個がすべて描ける。
- **線のラベル**: 線がラベルの層をまっすぐ通る所で線を横切って書き、ラベルの幅だけ線を切る（今と同じ:
  `──IP─/─CIDR──`）。縦の線はラベルの行数だけ切る。奇数の幅を中央に置くとき、余る 1 桁は右。
- **配置**: flowchart と ER は絵と同じ層の配置（並べ順・座標・トラックの割り当て）を、間隔をすべて配置ごとの
  整数セルのパラメータにし、ノードの大きさを整数セルに切り上げて走らせる。列とトラックはそれぞれ 1 度だけ、
  同じものとして整数の計算で格子に合わせる — 点ごとには合わせない（半セルの同点で直角が崩れる: 実測）。線の
  端とループの端は面の内側のセルだけを使い、角は使わない。自分への線はノードの脇に内側の 2 行を使うループ。
  両端の内側が同じ行（列）を持たないまっすぐな線は、途中で段を渡る。間隔は乱数の flowchart で測って
  決めた: 面の上の線の端は 2 単位おき（1 単位では 60% が衝突）、層の間は 1 行、矢印の前は 2 単位。実データの
  flowchart 22 個はすべて描け、乱数 4,000 個では 99.6%（残りは拒む）。ER は常に左から右（RL と書けば右から左）に並べる: 多重度は横の線に沿って読むため。TB の図も LR で描く —
  明記した違いで、関係は変わらない。層の間は 1 単位広く、矢印の前の余白は 1 多くし、ラベルと印の間に線の
  セルを 1 つ残す。エンティティから自分への関係は、他の線の端が無い内側の 2 行を使って表の右の面でループする
  （配置は下にループさせるが、そこでは印を横に読めない）。sequence は絵と同じく専用の列の配置。独立検証はこれを実データの
  flowchart 22 個（崩れ 0）と乱数 20,000 個（内側のセルと見出しの規則の前で 0.03% が衝突、すべて丸めの同点）
  で走らせた。
- **描くたびに確かめること**（絵の性質と同じく、格子の上で）: ノードの箱が 1 度ずつ描かれ、ラベルが
  すべて中にある。箱どうしが重ならない。線はどれも始点の箱から終点の箱までつながった線の文字の道で、
  他の箱に触れない。2 本の線がセルを共有するのは、まっすぐな区間どうしが直角に交わる所だけ — 他の線の上の
  角や T 字は欠陥。矢印のある端に矢印が 1 つ、箱の隣に。ラベルがすべてあり、箱や他の線にかからない。
  枠が所属するノードを収め、見出しが中にある。ER の印が自分の端にある。sequence のメッセージが順に並び、
  送り手の生存線から受け手の生存線へ。破れれば `LayoutFault` で、呼び出し側はソースを見せる。幅では拒まない:
  端末より広い罫線はそこで折り返り、高いものは流れる（gem-agent ADR-0063）。大きさの上限は 200 万セルだけ
  （構文が未対応と同じ扱い）: 絵が許す最大の図で最大 130 万（上下向きに並べた 299 枚の葉の星、4,868 × 267）、
  配置は 50 ms 未満だった。
- **組み込み**: gem-agent は `mermaid-ascii` と書き換えの表・2 つの確かめを外し、フェンスをこのエンジンに
  渡す（ADR-0042 / ADR-0063 を改める ADR）。罫線は今どおり Markdown の描画を通さず、TUI の無害化も通る。
  lagent も同じ形で罫線の経路を足す: `Segment` に罫線を持たせ、返答の描画がそのまま出す（ADR-0025、
  罫線の保留を退けた ADR-0024、ADR-0020 A1 を改める ADR）。

## 3. Design Decisions

- **Go で自前実装する。** 使う側の gem-agent と lagent がどちらも Go であることと、組織の外で書かれた
  コードを出荷しない組織の方針（ADR-024）のため。よく使われる作り方（mermaid.js をヘッドレスの Chrome
  で動かす mermaid-cli）は、組織の外のコードをそのまま出荷することになり、Chrome も必要で、起動も
  遅いので採らない。
- **`golang.org/x/image` への依存を認める**（運用者判断、2026-09-28）。フォントの読み込みと描画を
  自前で書くのは割に合わない。Go チームのものなので、一次提供物として扱う（gem-agent も既に
  `x/oauth2` と `x/sys` を直接使っている）。
- **ランタイムの描画機能として作り、モデルのツールにはしない**（運用者判断、2026-09-28）。図を描く
  ツールはモデルがほとんど使わず、使われない機能になる（gem-agent の `render_diagram` は 76 セッションで
  1 回しか呼ばれず、ADR-0063 で撤去した）。
- **gem-agent ADR-0089 の A3（mermaid を PNG にする案の却下）を改める。** A3 の理由は「ADR-0042 の
  忠実性の検査（ラベルが全部あるか・線の数が矢尻の数と合うか）は罫線レンダラのためにあり、PNG に
  すると検査も一緒に消える」だった。あの検査が必要だったのは、中身を見られない他人のレンダラの出力を
  文字列から逆算していたからである。自前のエンジンでは配置の結果を直接調べられるので、検査は
  エンジンの内側に移す。
  - 配置の検査: すべてのノード・線・ラベルが置かれている。ラベルどうし、ラベルとノード、ラベルと
    subgraph の見出しが重ならない。線が端点以外のノードの枠を通らない。多重の線が重ならない。
  - 読み違いは描く段階の検査では捕まらない（過去の失敗は、`-- 文字 -->` を別のノードと誤読した例の
    ように、ラベルは全部あるのにグラフが違うものだった）。これは公式仕様から起こした構文の表の
    テストと、実データの出力を人が 1 枚ずつ見る確認で守る（§4）。「間違いは仕組み上起きない」とは
    言わない。
  - 正式な改訂は、gem-agent への組み込み時の ADR で行う（ADR-0089 に Amended 注記を付ける）。
- **構文の読み取りは描き方と切り離す。** 第 2 段階で罫線表示を自前に置き換えるとき、同じ図の
  データを使うため。
- **白地のカード状の画像にする。** 端末の背景色を問い合わせると、BubbleTea では応答が入力欄に
  漏れた前例がある（gem-agent、2026-08-18）。白地なら明るい端末でも暗い端末でも読める。
- **間違いは防ぎ、見た目の良し悪しは判定しない**（gem-agent ADR-0042 の原則を引き継ぐ）。
  線の交差、図の大きさ、縮めたときの文字の小ささでは表示を拒まない。
- **資源の上限は設ける。** 見た目の判定ではなく、描画が止まらなかったりメモリを使い切ったりするのを
  防ぐため。値は実装時に実測して決める。
- **フォントは選べるようにする**（運用者の要望、2026-09-28）。ただし文字の欠けは間違いとして扱う。
- **OS が管理する役割は担わない。**

**補完する既存ツール**: gem-agent と lagent の `internal/termimg`（画像の表示）、gem-agent の
`internal/diagram`（mermaid フェンスの検出と罫線表示）。

**対象外**:

- flowchart・sequence・ER と、第 2 段階で加えるもの（2026-09-29 の運用者の判断で pie・state・gantt・
  mindmap）以外の図。class、journey、gitGraph などは予定しない。
- テーマ、色の指定、style の反映。
- SVG の出力。
- sixel、および画像を出せない端末への画像表示。これらはいまの表示のまま。
- mermaid の書き方の誤りを直すこと（誤りはエラーにしてソースを表示する）。
- モデル向けのツール、およびシステムプロンプトでの図の指示。

## 7. External Platform Constraints

- 画像を出せる端末は iTerm2 と kitty の方式に限られる。表示できるかの判定と、占める行数・桁数の
  宣言は既存の termimg が担う（gem-agent ADR-0089）。sixel は占める行数を宣言できないので対象外。
- 画像 1 枚あたりの上限は `termimg.MaxBytes`（2MiB）。
- 画像 1 枚を送ってから端末が次の問い合わせに応答するまでは、iTerm2 で 17〜105ms、kitty で 15〜106ms
  （PNG 59〜267KB、段 0 の実測）。端末が受け取りを終えるまでの上限であって、描き終えるまでの時間ではない。
- セルの縦横比は端末と設定で変わる（段 0: iTerm2 は 2.25、kitty は 1.86）。kitty は宣言した行数・桁数
  いっぱいに画像を置くので、比を誤ると図が歪む可能性がある。比は `TIOCGWINSZ` から得る（§2）。
- フォントは macOS のシステムフォントに依存する。対象は macOS だけ（gem-agent と lagent も
  darwin/arm64 専用）。
